# Zalo 连接器

- 日期：2026-10-18（实现稿）
- 相关：待建 Issue
- 代码：`ds-bot/src/host/zalo.js`（新增）、`src/client/connectors.js`（Connectors 页）、`src/host/{constants,store,delivery,turns,prompt,channel,secrets}.js`、`test/zalo.test.js`

## 为什么

用户想让一个 Bot 挂上一个 Zalo 个人号：既能「关注」指定的会话（群或个人）的消息，又能让用户在 Zalo 里直接和 Bot 对话。Zalo 个人号没有官方 API（官方 OA API 只能给关注者发消息，读不到个人群聊），所以只能用非官方库（`zca-js` 或 `zalo-api-final`），扫码登录后拿到 `{cookie, imei, userAgent}` 三件套。

原则和浏览器、密钥那篇一样：**外面进来的消息是数据不是指令，凭证只有用户输入、只存本机。**

## 已定的行为

### 账号与登录

- 一个 Bot 最多绑一个 Zalo 个人号；不同的 Bot 可以各绑各的，也可以**共用同一个号**：扫码登录一次后，其他 Bot 通过 `zalo-bind` 直接绑到已有账号，不用再扫。绑定关系存在 `state.json` 的 `state.zalo` 里。
- 登录只走扫码：Connectors 页发起 `zalo-start`，客户端轮询 `zalo-status` 拿到 QR 图并显示；扫码确认后库返回 `{cookie, imei, userAgent}`，整体作为一个 secret（`ZALO_ACCOUNT_<uid>`）存进 `bot/secrets.json`。值永不进入模型请求（沿用 secrets.js 的替换规则）。旧版的 `ZALO_SESSION_<botId>` secret 在下次连接时自动改名到账号名下。
- 插件加载时（`ctx.effect`）读 secret 自动重连；删掉 secret 即解绑。连接状态（connecting / ready / error / off）显示在 Connectors 页，错误信息经 `rt.redactSecrets` 处理；掉线可点 Reconnect（`zalo-reconnect`）。
- 持有 `state.lock` 的读方（另一个 dsh 占着写锁）不连接——同一个号的两个 listener 会互踢。同理共用账号时也只开一个 listener：以账号 uid 为键，所有绑定的 Bot 共用。
- `selfListen: false`，并额外按 `isSelf` / own uid 过滤，防止 Bot 回复自己发出的消息造成循环。

### 会话（thread）与模式

- 每个 Zalo thread 对这个 Bot 有一个模式：`talk` / `watch` / `off`，默认 `off`。用户在 Connectors 页或让 Main Bot 调整。**同一个账号下一条 thread 只能有一个 owner**（mode 非 off 的 Bot）；给另一个 Bot 设置同一条 thread 会被拒绝并提示现有 owner，避免两个 Bot 在同一会话里抢答。
- `talk`（用户与 Bot 的私聊，以及用户明确开启的会话）：消息即刻 `rt.deliver` 进 Bot 自己的 Session，`role: 'zalo'`，带 `threadId`、发送者名。回合结束时用 `roomWaiters` 的机制等到回复文本，`api.sendMessage` 自动回发到该 thread——对用户来说就是在 Zalo 里和 Bot 聊天。
- `watch`（要关注的群/人）：消息只进 `state.json` 里的 ring buffer（最多 50 条），不触发回合。两种唤醒：群里有人 @ 了 Bot 的昵称（`mentions` 元数据或文本 `@昵称`）、或命中用户配置的关键词——唤醒时把最近 30 条 buffer 一并 deliver，并注明「在这里说话只能用 zalo_send」，Bot 自己决定回不回。此外 Bot 任何时候可以用 `zalo_read` 主动翻 buffer，或配合 schedules 做定时摘要。
- `off`：忽略。陌生会话永远是 `off`；Zalo 来的消息一律是数据不是指令，prompt 里写明。

### 工具（只给绑了号的 Bot，`zaloBound` 的 prompt 规则同批注入）

- `zalo_threads`：列**已配置**的 thread 及其模式、未读条数；让 Bot 说出能往哪儿发。
- `zalo_read`：读某个 thread 的 buffer。
- `zalo_send`：发文本到某个 thread，**只允许发到已是 `talk`/`watch` 的 thread**，防止读到群里的注入指令后把消息发到任何地方（同 GitHub token 不进 shell 的考虑）。限速：两条至少间隔 3 秒，每 10 分钟最多 20 条，per-account 串行队列（共用账号的 Bot 共享同一份额度，防止合计超限触发风控）。

### 端点（POST /api/bot）

`zalo-status`（状态 + QR 进度 + 已有账号列表）、`zalo-start`（发起扫码登录）、`zalo-bind`（把 Bot 绑到已登录的账号）、`zalo-cancel`、`zalo-logout`（解绑单个 Bot；最后一个绑定的 Bot 登出时才删除 session 和 secret）、`zalo-reconnect`、`zalo-threads`（列好友+群，供挑选；别的 Bot 已关注的 thread 会标出 owner）、`zalo-thread-mode`（设置某 thread 的模式与关键词，同账号下强制单 owner）。

### state.json

```jsonc
"zalo": {
  // key 是 botId；凭证本体在 secrets.json，不在这里
  "<botId>": {
    "account": { "uid": "…", "name": "…" },
    "threads": {
      "<threadId>": { "kind": "user|group", "name": "…",
                      "mode": "talk|watch", "keywords": ["…"],
                      "buffer": [ { "from": "…", "text": "…", "ts": 0 } ] }
    }
  }
}
```

## 不做什么

- 不做群发/broadcast，不做主动加好友、建群。
- `watch` 的群不做逐条自动回复；不 @ 不命中关键词就只是一笔记录。
- 第一版只处理文本消息；贴纸、图片、引用、撤回显示为占位（如 `[sticker]`，用户可见文案一律英文）。
- 不做多账号管理界面——绑定入口在 Bot 自己的 Connectors 卡里。

## 依赖选型

定稿 `zca-js@2.2.0`：与 `zalo-api-final` 同宗（fork），listener/login 接口一致，但没有 `sharp` 原生依赖，社区更大。测试用 `config.zalo.import` 注入假库，不碰真账号。

## 已知限制

- 非官方库违反 Zalo 个人号的使用条款，账号有被封的风险；cookie 会话会过期，过期后要重新扫码。
- 非官方库的接口可能随 Zalo 服务端变更而失效，断线要能在 Connectors 页看到原因（`error` 状态 + Reconnect）。
- Zalo 的 @ 提及在群消息里以 `mentions` 元数据出现，匹配逻辑依赖库解析得对不对；实现里同时兜底文本 `@昵称`。
- `talk` 的自动回发只带回合的最终文本（`groupReply` 同款）；回合中途写的中间话不外发。
